Rambu app map

Rambu warns older parents about scam calls while the call is still going. A puck (for now, the Mac's microphone) hears the loudspeaker call, the backend transcribes it and asks an AI model for scam signals with exact quotes, the family gets a warning, and a caregiver's Scam tap turns the parent's phone into a full-screen "hang up" alarm.

One action, end to end: the caregiver taps Scam

Reference route (read it in your editor; it wasn't toured live).

1
ios/Rambu/Caregiver/AlertDetailView.swift — search model.decide(alert, scam: scam). The Scam button calls AppModel.decide in ios/Rambu/App/AppModel.swift, which posts the verdict to the backend.
2
backend/rambu/alerts.py — def decide. Inside one SQLite transaction the first caregiver's answer is stored; anyone later gets the existing decision back. Then FamilyNotifier.verdict in backend/rambu/push.py pushes the verdict, and _repeat_scam_alarm repeats "HANG UP NOW" every 6 s (SCAM_ALARM_REPEATS = 5) until the parent acknowledges.
3
ios/Rambu/App/RambuApp.swift — search needsHangUp. When the newest alert has an unacknowledged scam verdict, the overlay shows ScamTakeoverView (ios/Rambu/Parent/ScamTakeoverView.swift). "I hung up" calls POST /api/alerts/{id}/acknowledge, which stops the repeats.
Where the warning itself comes from

backend/rambu/pipeline.py → CallWorker._analyze runs on every ~3 s of audio. backend/rambu/analyze.py → validate keeps only quotes that appear word for word in the transcript; safety_net catches plain requests for a code if the model misses them. The model instructions are in backend/rambu/prompt.md.

To change this, start here

  • Push wording (English/Indonesian): backend/rambu/i18n.py.
  • In-app wording: the lang.t("English", "Indonesian") pairs next to each view.
  • How hard the alarm nags: SCAM_ALARM_REPEATS and SCAM_ALARM_INTERVAL in backend/rambu/push.py; sound, vibration and voice in ScamAlarm.
  • What counts as a scam signal: backend/rambu/prompt.md, plus _CODE_REQUESTS in analyze.py.
  • Colors and type: ios/Shared/Brand.swift.

A practice to reuse

When a step fails quietly, read the outside service's own reason before changing code. Here, warnings reached the screens through polling but Apple refused the pushes. The backend log showed 400 TopicDisallowed, which pointed at the App ID rather than at the push code. One signed device build registered id.rambu.app with push, and the next run logged 200 OK (recorded under Revisions in devpost/checklist.md). The same habit found the silent microphone: ffmpeg's device list showed input :0 was a Zoom virtual device.

Run it again

Backend: cd backend && uv run uvicorn rambu.main:create_app --factory --port 8001 --env-file .env
App: cd ios && xcodegen generate && open Rambu.xcodeproj, run on two simulators.
Listening: uv run --project backend python tools/mac_puck.py. Full steps are in README.md.
